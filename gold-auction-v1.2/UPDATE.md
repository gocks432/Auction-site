# GOLD 경매장 v1.2 — 입찰만 하고 학급 홈페이지에서 처리

## 확인 결과

2026-09-17 현재 상태창 공식 공개 홈페이지와 기본 가이드의 공개 본문, 공개 검색 결과를 확인했습니다. 외부 서비스가 학생 GOLD를 읽는 공식 API 문서, 인증 키 발급 방법, 외부 연동 안내는 찾지 못했습니다.

- 공식 홈페이지: https://www.statyou.kr
- 기본 가이드: https://www.statyou.kr/ko/guide

첨부 화면에는 학생의 355 GOLD가 표시되어 있지만, 오른쪽은 Elements(화면 구조) 탭입니다. 이것만으로 외부 Apps Script가 학생 잔액을 조회할 수 있는지는 판단할 수 없습니다. 로그인한 교사의 비공개 통신이나 서비스 운영자 문서는 확인하지 못했으므로 **연동 불가능이 확정된 것은 아닙니다. 현재 안정적으로 연결할 공개 근거가 없는 상태**입니다.

추후 운영자가 교사 권한의 공식 API를 제공한다면, 학생 식별자 매핑·인증·잔액 조회를 구현할 수 있습니다. 동시에 여러 경매/상점에서 지출하는 것을 정확히 막으려면 잔액 조회뿐 아니라 금액 예약 또는 원자적 차감 기능도 필요합니다. 현재 버전에는 외부 사이트 로그인 세션이나 쿠키를 복사하는 기능을 넣지 않았습니다.

요청하신 대안에 따라 이번 업데이트는 **보유 GOLD와 무관하게 입찰 → 낙찰 금액 기록 → 교사가 학급 홈페이지에서 별도 처리**하는 방식입니다.

## 바뀐 동작

| 항목 | v1.2 |
|---|---|
| 학생 보유 GOLD 조회 | 조회하지 않음 |
| 경매 사이트 GOLD 지급·차감 | 하지 않음. 기존 지급 API도 차단 |
| 입찰 제한 | 보유 잔액과 무관. 시작 금액·입찰 단위·시간·참여 대상 규칙은 유지 |
| 금액 범위 | 정수 GOLD, 최대 100,000,000 (잘못된 입력 방지 상한) |
| 공개 경매 | 현재 최고 금액보다 높은 금액 제출 |
| 비공개 경매 | 마감 전 수정·철회 가능. 동점은 최종 금액 선접수 우선 |
| 마감 | 낙찰자와 낙찰 금액 결정, 외부 처리 대기로 기록 |
| 교사 메뉴 | GOLD 관리 대신 ‘낙찰금 처리’ |
| 학생 메뉴 | 내 GOLD 제거. 계정 잔액과 묶인 GOLD 표시 제거 |
| 쿠폰 | GOLD 처리 확인 전에는 사용 대기, 확인 후 사용 가능 |

이 사이트가 돈을 실제로 받거나 상태창의 GOLD를 변경하는 기능은 없습니다. ‘학급 홈페이지 처리 완료’는 교사의 확인 기록을 남기는 버튼입니다.

## 운영 순서

1. 교사는 기존처럼 경매 상품·시간·공개/비공개 방식을 설정합니다.
2. 학생은 ‘낙찰되면 이만큼 내겠습니다’라는 의미로 금액을 입력합니다.
3. 경매 종료 후 **교사 → 낙찰금 처리**를 엽니다.
4. 학생 번호·닉네임·낙찰 금액을 확인합니다.
5. 상태창 학급 홈페이지에서 해당 학생의 실제 GOLD를 직접 처리합니다.
6. 경매 사이트로 돌아와 **학급 홈페이지 처리 완료**를 누릅니다.
7. 처리 메모를 적고 확인합니다. 실제 처리한 후에만 이 버튼을 누릅니다.
8. 학생의 쿠폰이 사용 가능한 상태로 바뀝니다.

쿠폰 기한은 외부 처리 완료를 확인한 시점부터 설정한 일수만큼 적용합니다. 실제 GOLD가 부족해 아직 처리하지 못했다면 ‘처리 대기’로 두고 학생과 해결한 뒤 완료 처리합니다. 이 버전에서는 차순위 자동 낙찰·미납 자동 취소를 하지 않습니다.

## 이미 있던 기록은 어떻게 되나요?

- 학생 계정·교사 비밀번호·아바타·과거 기록은 유지합니다.
- 새 버전이 처음 서버 요청 또는 마감 트리거를 처리할 때, 기존의 **시작 대기/예정/진행 중 경매도 입찰 전용 방식으로 자동 전환**합니다.
- 기존 입찰 금액은 유지하며, 미종료 경매의 잔액 제한·GOLD 묶임·자동 차감은 없앱니다.
- 이미 종료되어 구버전에서 차감된 거래와 발급된 쿠폰은 그대로 보존합니다. 과거 차감을 자동으로 환불하거나 학급 홈페이지에 반영하지 않습니다.
- 과거 경매 사이트 잔액은 기록으로 보존하지만, 이후 입찰 판정에는 사용하지 않습니다.
- 새 방식으로 종료된 낙찰 건만 ‘낙찰금 처리’에 표시됩니다. 이전에 종료된 경매는 여기서 다시 처리하지 않습니다.

운영 중 규칙이 바뀌므로 경매를 진행하지 않는 시간에 업데이트하고, 학생에게 이제 잔액 제한 없이 입찰한다는 점을 안내하세요.

## 적용 방법 — 4개 파일 교체

1. 기존 사이트의 **설정 · 백업 → JSON 백업 다운로드**로 현재 데이터를 보관합니다.
2. 이 ZIP을 압축 해제합니다.
3. 기존 Apps Script 프로젝트를 엽니다. 새 프로젝트를 만들지 않습니다.
4. 다음 파일을 각각 전체 교체합니다.

| Apps Script 파일 | 복사할 파일 |
|---|---|
| Code.gs | Code.gs 또는 copy-as-text/Code.gs.txt |
| Core.gs | Core.gs 또는 copy-as-text/Core.gs.txt |
| Pdf.gs | Pdf.gs 또는 copy-as-text/Pdf.gs.txt |
| Index.html | Index.html 또는 copy-as-text/Index.html.txt |

메모장에서 .txt 파일을 열어 Ctrl+A → Ctrl+C, Apps Script의 해당 코드 영역에서 Ctrl+A → Ctrl+V로 교체하면 됩니다. .txt는 원본과 같은 내용입니다.

5. Ctrl+S로 저장합니다.
6. **배포 → 배포 관리 → 기존 배포 편집(연필) → 새 버전 → 배포**합니다.
7. 기존 웹 주소를 새로고침합니다. 학생 기기도 새로고침합니다.
8. 기존 교사 비밀번호로 로그인하고 ‘낙찰금 처리’ 메뉴를 확인합니다.

**initialize_ 또는 setupAuction을 실행하지 않습니다.** 스크립트 속성·데이터 시트는 그대로 두고, appsscript.json이나 Drive 서비스도 수정하지 않습니다.

v1.1을 아직 적용하지 않았어도 이 4개 파일로 v1.0에서 바로 업데이트할 수 있습니다. 학생 코드→PIN 로그인, 배경·학교 로고, PDF 계정 가져오기, 학생별 수동 수정 기능도 포함됩니다.

## 시험 운영

- 잔액이 0인 학생도 시작 금액 이상의 유효한 금액으로 입찰되는지 확인.
- 마감 후 낙찰 금액이 표시되고 ‘낙찰금 처리’에 처리 대기 건이 생기는지 확인.
- GOLD를 자동 차감하거나 지급하는 화면이 없는지 확인.
- 처리 확인 전 쿠폰 사용 요청이 막히는지 확인.
- 교사가 처리 완료를 기록한 뒤에만 쿠폰 사용 요청이 가능한지 확인.

서버 로직/API 모의 테스트 23개(과거 내부 잔액 방식의 기록 호환 테스트 포함), 저장소 테스트 2개, DOM 화면 동작 테스트 6개를 통과했습니다. 합계 31개입니다. 외부 처리 표시에서 실제 잔액이 변하지 않는 것, 학생의 처리 완료 요청 거부, 중복 요청 시 중복 처리 방지도 확인했습니다.

실제 Google 배포와 태블릿 화면 확인은 사용자의 기존 프로젝트에서 진행해야 합니다. 상태창 연동은 구현하지 않았으며, 해당 사이트의 GOLD는 이 코드로 변경되지 않습니다.

## GitHub 저장

GitHub에는 Code.gs, Core.gs, Pdf.gs, Index.html과 이 안내서만 업데이트하면 됩니다. 실제 학생 PDF·계정 정보·GOLD 백업은 업로드하지 않습니다. GitHub 저장소나 Google 배포를 이번 작업에서 직접 변경하지는 않았습니다.
